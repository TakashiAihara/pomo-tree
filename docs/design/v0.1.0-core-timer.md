# pomo-tree v0.1.0 design doc — メニューバー常駐ポモドーロタイマー

status: draft（承認待ち）
date: 2026-07-07
author: TakashiAihara (+ Claude)

## 概要

macOS メニューバー / Windows システムトレイに常駐するポモドーロタイマーを Tauri v2 (Rust) で作る。
macOS ではメニューバーに残り時間テキスト（例: `🍅 24:31`）を常時表示し、トレイメニューから開始/一時停止/スキップを操作できる。

プロダクト名はレストラン「ポムの樹」に由来する。「tree」には将来構想が 2 つある（v0.1 スコープ外だが設計の布石を打つ）:

1. トマトの樹（育成ビジュアル）: ポモドーロをこなすほど架空の「トマトの樹」が育ち、トマトが実る。大きいタスクほど大きいトマトが実る（v0.2 想定）
2. タスクツリー: タスクを木構造で管理しポモドーロを紐付ける（v0.3 想定）。「タスクの大きさ → トマトの大きさ」の対応はこのタスク紐付けが前提になるため、v0.2 の時点ではセッション数ベースの育成から始め、v0.3 でタスク連動に拡張する

## v0.1 スコープ

### 含む

1. タイマー本体: 作業 / 短休憩 / 長休憩のサイクル（デフォルト 25/5/15 分、4 ポモドーロごとに長休憩）
2. メニューバー / トレイ表示:
   - macOS: アイコン + 残り時間テキスト（`set_title`）
   - Windows: アイコン（状態別の色）+ tooltip に残り時間
   - トレイメニュー: 開始 / 一時停止 / 再開 / スキップ / リセット / 設定を開く / 終了
3. 通知: セッション終了時に OS ネイティブ通知（サウンド付き）
4. 設定画面: 作業/短休憩/長休憩の分数、長休憩までのポモドーロ数、自動で次セッションを開始するか、通知サウンド有無
5. セッション履歴の記録のみ（表示 UI なし）: 完了セッションをローカルに追記保存。v0.2 の木育成・統計の布石

### 含まない（将来バージョン）

1. 木育成ビジュアル・統計/履歴画面（v0.2）
2. タスクツリー管理（v0.3）
3. 自動起動（login item）、メニューバーのポップオーバー UI、Windows の数字描画アイコン（v0.1.x で検討）
4. Linux 対応（tray の title / left-click 挙動に制約が多いため明示的にスコープ外。ビルドが通る分には壊さない）

## 技術スタック

| レイヤ | 採用 | 理由 |
|--------|------|------|
| アプリ基盤 | Tauri v2 | トレイ API 内蔵（macOS title 対応を deepwiki で裏取り済み）、通知/ストアのプラグインが揃う、dmg/msi バンドル、将来のリッチ UI（木育成）に耐える |
| コアロジック | Rust（Tauri backend） | タイマー状態機械は Rust 側に一元化。UI はあくまで表示 |
| フロントエンド | Vite + React + TypeScript | 設定画面程度なら何でもよいが、v0.2 の木育成ビジュアル（canvas/SVG アニメーション）でエコシステムが厚い React を先に敷く |
| パッケージ管理 | Bun | ユーザー標準スタック |
| 通知 | tauri-plugin-notification | OS ネイティブ通知 |
| 設定永続化 | tauri-plugin-store | JSON ストア。設定画面との read/write が素直 |
| セッション履歴 | JSON Lines（自前、`app_data_dir/sessions.jsonl`） | v0.1 は追記のみ。v0.2 で集計要件が固まった時点で SQLite 移行を判断 |

### 検討した代替案と却下理由

1. 純 Rust 常駐型（tray-icon + muda + winit/tao）: 依存最小だが、設定画面・木育成ビジュアルを後から足すコストが高い。tree 構想が確定しているため却下
2. egui / Slint + tray-icon: webview なしで窓 UI を持てるが、トレイ連携・配布パッケージングの自前配線が増える。Tauri が同じ tray-icon を内蔵しつつ配布まで面倒を見るため優位性がない
3. Electron: Rust 希望に反する。メモリフットプリントも常駐アプリに不向き

## アーキテクチャ

### 責務分割

```text
src-tauri/ (Rust)
├── timer/          タイマー状態機械（純粋ロジック、OS 非依存、unit test 対象）
│   ├── state.rs    Phase (Work/ShortBreak/LongBreak) × Status (Idle/Running/Paused)
│   └── engine.rs   tick 駆動、遷移イベント発火
├── tray.rs         トレイ生成・title/tooltip/icon 更新（プラットフォーム差分をここに閉じ込める）
├── notify.rs       セッション終了通知
├── store.rs        設定 read/write（tauri-plugin-store）
├── history.rs      セッション履歴 append（JSONL）
└── lib.rs          Tauri setup、コマンド定義、イベント配線

src/ (TypeScript)
└── 設定画面のみ（タイマー状態は Rust からのイベント購読で表示）
```

### 設計原則

- タイマーの正は Rust 側の 1 箇所のみ。フロントエンドは `timer://tick` / `timer://phase-changed` イベントの購読者であり、状態を持たない
- tick は経過時間ベースで計算する（`Instant` 起点の残時間算出）。1 秒 interval の減算カウンタにはしない（スリープ復帰・イベントループ遅延でズレるため）
- スリープ復帰時の扱い: 復帰時に経過時間を再計算し、作業セッション中に期限超過していたら「終了扱い + 通知」とする
- プラットフォーム差分（macOS title / Windows tooltip+icon）は `tray.rs` の 1 モジュールに閉じ込め、engine 側は `TrayPresenter` 的な trait 越しに更新を依頼する

### macOS 固有

- `ActivationPolicy::Accessory` で Dock アイコン非表示（メニューバー専用アプリ化）
- title 更新は毎秒。`MM:SS` 固定幅でメニューバーの幅ブレを防ぐ

### Windows 固有

- title は tray-icon 側で no-op（deepwiki 裏取り済み）。v0.1 は tooltip + 状態色アイコン（作業=赤系 / 休憩=緑系 / 停止=グレー）で代替
- 数字を描画した動的アイコンは v0.1.x の enhancement（`image` crate でのラスタ描画を想定）

## データモデル

### 設定（store）

```json
{
  "workMinutes": 25,
  "shortBreakMinutes": 5,
  "longBreakMinutes": 15,
  "pomodorosUntilLongBreak": 4,
  "autoStartNext": false,
  "notificationSound": true
}
```

### セッション履歴（JSONL、1 行 1 セッション）

```json
{"phase":"work","startedAt":"2026-07-07T10:00:00+09:00","endedAt":"2026-07-07T10:25:00+09:00","completed":true}
```

completed: スキップ/リセットで中断した場合 false。トマトの樹（v0.2）は completed=true の work セッションを育成素材にする想定。v0.3 でタスク紐付けが入ったら `taskId` フィールドを追加し「タスクの大きさ → トマトの大きさ」に拡張する（JSONL は行単位でスキーマ拡張に強い）。

## テスト方針

1. Rust unit test: 状態機械の遷移全パターン（開始/一時停止/再開/スキップ/リセット/満了/長休憩判定/スリープ復帰の期限超過）を網羅。ロジックを OS 非依存に切ってあるのはこのため
2. Rust unit test: 履歴 append と設定 roundtrip
3. E2E: tauri-driver が macOS 非対応のため v0.1 では自動 E2E を張らない。リリース前に手動スモーク（macOS 実機 + Windows）で担保し、チェックリストを `docs/` に置く
4. フロントエンドは設定フォームのみで分岐が薄いため v0.1 では unit test 対象外（木育成 UI が入る v0.2 で導入判断）

## CI / 配布

1. GitHub Actions: macOS (aarch64) + Windows (x86_64) のビルド + `cargo test` + `cargo clippy`
2. 配布: tauri-action で dmg / msi を Release にアタッチ（tag push 駆動）。コード署名・notarization は v0.1 では扱わない（自分用配布）

## マイルストーン分割（PR 単位）

1. PR1: Tauri v2 scaffold + トレイ常駐 + macOS title 固定文字列表示（Dock 非表示含む）
2. PR2: タイマー状態機械（Rust unit test 込み）+ トレイ title/tooltip のカウントダウン + メニュー操作
3. PR3: 通知 + セッション履歴記録
4. PR4: 設定画面 + store 永続化
5. PR5: CI（build + test + clippy）と release workflow

各 PR 単体で動作する状態を保つ（PR1 の時点で常駐アプリとして起動可能）。
